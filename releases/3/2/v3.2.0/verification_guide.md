# 🧪 Інструкція з перевірки функціоналу LLiMo.v3 (v3.2.0 Verification Guide)

Цей посібник містить практичні кроки для перевірки всіх можливостей релізу **v3.2.0**, зокрема завантаження воркфлоу, виконання автономних агентських команд, точкової заміни коду (Line-Range Replacement) та інтерактивного меню валідації.

---

## 🛠️ Передумови
Переконайтеся, що всі залежності встановлені та проєкт успішно збирається:
```bash
pnpm install
pnpm --filter @nan0web/llimo.v3 build
```

---

## 📋 Крок 1: Запуск з воркфлоу (CLI `-w` / `--workflow`)
Перевірте можливість передачі аліасу воркфлоу через консоль:
```bash
llimo3 task_extend.md -w docs-stories
# або з локальним шляхом:
node apps/llimo.v3/bin/llimo.js task_extend.md -w docs-stories
```
**Що очікується:**
- Додаток розпізнає параметр `-w` та завантажить вказаний файл воркфлоу з БД (`@data/uk/workflows/docs-stories.md` або англійський fallback).
- Вміст воркфлоу буде автоматично додано до системного промпту.

---

## 🤖 Крок 2: Автономні команди агента (`@ls`, `@get`, `@search`)
Для перевірки роботи внутрішніх інструментів моделі без використання стороннього API, запустіть тестовий набір:
```bash
pnpm --filter @nan0web/llimo.v3 test
```
**Що очікується:**
- Тест `should execute agent commands @ls, @get and @search correctly` має пройти успішно.
- Модель може повернути блок виду:
  ```markdown
  ---boundary:@ls---
  apps/llimo.v3/src/domain
  ---boundary---
  ```
  Система автоматично виконає читання структури та поверне результат у наступну ітерацію діалогу, без потреби ручного підтвердження розробником (оскільки це безпечні операції читання).

---

## 🩹 Крок 3: Точкова заміна коду (Line-Range Replacement)
Модель може оновлювати файли точково за номерами рядків для збереження контексту та економії токенів.
**Формат виходу моделі:**
```markdown
---boundary:apps/share.app/src/domain/TelegramAdapter.js:15:3---
// Новий вміст для заміни 3-х рядків починаючи з 15-го рядка
const key = 'new_value';
console.log(key);
---boundary---
```
**Як перевірити:**
- Запустіть юніт-тест:
  ```bash
  node --test apps/llimo.v3/src/domain/app/ChatSessionModel.test.js
  ```
- Тест `should perform inline snippet replacement using startLine and lineCount` автоматично моделює цей процес та перевіряє коректність модифікації вмісту.

---

## 🩹 Крок 4: Фолбек на класичний Diff-патч
Якщо модель повертає зміни у форматі diff (використовуючи `+` та `-`) без вказання точних номерів рядків:
```markdown
---boundary:apps/share.app/src/domain/TelegramAdapter.js---
<<<<<<<
-old_line
+new_line
=======
```
**Що очікується:**
- Система автоматично перемкнеться на метод `applyPatch`, знайде відповідні рядки у оригінальному файлі та замінить їх.
- Тест `should apply diff patch fallback when startLine/lineCount are not specified` підтверджує працездатність цього механізму.

---

## 🛡️ Крок 5: Інтерактивне меню та підтвердження запису
При реальній роботі в терміналі:
1. Система знаходить змінені файли та виводить промпт:
   ```
   Do you want to save the modified files? ... no / yes
   ```
2. Якщо ви обираєте **no** — зміни не записуються на диск, і виводиться:
   `✓ File changes discarded`.
3. Якщо ви обираєте **yes** — файли зберігаються, і відкривається меню валідації:
   ```
   Select post-generation verification action: 
   > Run tests (pnpm test)
     Run linter/formatter check (npm run lint)
     Run project validators (pnpm test:validate)
     Continue chat session
   ```
   У разі вибору тестів, ви отримаєте компактну однорядкову статистику результатів запуску.

---

## 🛠️ Крок 6: Перевірка парсингу NaN0 з одинарними лапками (Single Quotes Support)

Було оновлено парсер `NaN0.js` у `@nan0web/types`, додавши підтримку автоматичного зняття одинарних лапок (`'...'`) подібно до подвійних лапок. Це усуває проблему появи зайвих лапок у значеннях та шляхах при читанні конфігурацій `nan0web.nan0` та інших конфігів у форматі NaN0.

**Як перевірити:**
- Запустіть юніт-тести в `@nan0web/types`:
  ```bash
  pnpm --filter @nan0web/types test
  ```
- Тест повинен підтвердити, що парсер `NaN0.parse()` тепер успішно обробляє поля виду `key: 'value'` та повертає чисте значення `value` без одинарних лапок.
