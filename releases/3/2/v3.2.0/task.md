## 🌐 Web Routing & SEO Architecture (Локалізація без редіректів)

Для забезпечення OLMUI-паритету та збереження високого рівня SEO-оптимізації, впроваджено наступну модель маршрутизації та локалізації:

### 1. Визначення локалі без редіректу
* Коли користувач заходить на загальну сторінку (наприклад, `http://localhost:3000/docs`), сервер зчитує заголовок `Accept-Language` або cookies для визначення цільової мови (наприклад, `uk`).
* `PagesRouter` напряму підвантажує відповідний локалізований ресурс `data/uk/docs.nan0` і рендерить фінальну HTML-сторінку на сервері (SSR).
* **Жодних HTTP 301/302 редіректів** для початкового запиту не виконується, що пришвидшує час завантаження (First Contentful Paint) та усуває зайві мережеві запити.

### 2. SEO-оптимізація та Індексація
Для того щоб пошукові роботи (Googlebot тощо) коректно індексували всі мовні версії сторінок без плутанини:
* **Альтернативні посилання (`hreflang`)**: В `<head>` кожної сторінки сервер автоматично інжектує мета-теги `link rel="alternate" hreflang="x"`, що вказують на явні мовні адреси (наприклад, `<link rel="alternate" hreflang="uk" href="/uk/docs" />` та `<link rel="alternate" hreflang="en" href="/en/docs" />`).
* **Канонічні теги (`canonical`)**: Сторінка містить `<link rel="canonical" href="..." />`, яка чітко визначає первинну адресу документа.
* **Явні URL-шляхи**: Роутер продовжує підтримувати явні мовні префікси в URL (наприклад, `/uk/docs`), які є повністю статичними і легко обходяться пошуковими роботами.
* **Sitemap.xml**: Генератор автоматично включає всі можливі комбінації мовних шляхів до файлу карти сайту.
