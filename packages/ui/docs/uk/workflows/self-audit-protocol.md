# 🛡️ Sovereign Self-Audit Protocol (Протокол самостійного архітектурного аудиту)

Цей воркфлоу визначає суворий, обов'язковий протокол самоперевірки для AI-асистента перед завершенням будь-якої задачі або фіксацією змін у монорепозиторії.

---

## 🎯 Основні цілі протоколу

1. **Повна ізоляція системного середовища (Zero-Hallucination API)**: Повне вилучення прямого використання системних бібліотек Node.js (`node:fs`, `process.cwd`, `process.exit`) у доменних моделях. Уся взаємодія з даними та файлами має здійснюватися через агностичний абстрактний шар `this._.db`.
2. **Абсолютна локалізація (i18n Sovereignty)**: Заборона хардкоду будь-яких UI повідомлень або текстової конкатенації в генераторах команд. Усі системні текстові виводи мають зберігатися у `static UI` відповідного класу та викликатися через функцію `t()` з динамічними параметрами.
3. **Автоматична гігієна пакета (Ecosystem Pipeline)**: Перед здачею роботи AI-асистент зобов'язаний самостійно запустити перевірку лінтерами, тайп-чекером та тестами, щоб гарантувати повністю зелений статус.

---

## 🔍 Обов'язковий чек-лист перевірки

При кожній зміні коду асистент повинен виконати наступні три кроки валідації:

### 1. Перевірка на прямий системний імпорт (System API Isolation)
За допомогою `grep_search` сканувати змінені модулі на наявність рудиментів:
* **FS Leaks**: Жодних імпортів `fs` або `node:fs`. Замість цього використовуйте методи бази даних, наприклад:
  ```js
  const stat = await tempDb.statDocument('pnpm-workspace.yaml')
  if (stat.exists) { ... }
  ```
* **Process / Env Leaks**: Перевірити відсутність `process.env` чи `process.cwd()`. Усі конфігурації мають передаватися через конструктор та `this._`.
* **Exit Leaks**: Уникати `process.exit()`. Для завершення роботи команд використовувати `yield show(...)` та `return`.

### 2. Перевірка UI та Локалізації (Intent & i18n Hygiene)
* **Заборона конкатенації**: Рядки типу `` `[${project}] Error: ` + msg `` є критичним антипатерном.
* **Переклад через параметри (Late-Bound params)**: Усі повідомлення мають декларуватися у статичному реєстрі `UI` і викликатися наступним чином:
  ```js
  static UI = {
      errorIndexing: 'Error indexing {project}: {message}',
  }
  // ...
  yield log('error', t(UI.errorIndexing, { project: name, message: err }))
  ```
* **Жодних лінивих імпортів UI**: Використовувати статичні імпорти на початку файлу (наприклад, `import { show, log } from '@nan0web/ui'`) замість динамічних `await import('@nan0web/ui')`.

### 3. Автоматичний запуск Валідаційного Конвеєра (Automated Pipeline Validation)
Запустити з робочої папки пакета:
```bash
npm run test:all
```
Переконатися, що:
* Усі 100% модульних тестів зелені (`test`).
* Усі 100% історій SpecRunner пройшли (`test:stories`).
* Документація верифікована (`test:docs`).
* TypeScript компілятор пройшов без зауважень (`tsc`).
* Форматування відповідає стандартам (`prettier --check`).
* Knip підтверджує відсутність мертвого коду (`knip --production`).
