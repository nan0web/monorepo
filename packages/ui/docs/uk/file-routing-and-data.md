# 📂 Файлова Маршрутизація та Збереження Даних

NaN•Web покладається на прості детерміновані структури для маршрутизації екранів додатків та роботи з контентом.

---

## 🗺️ Файлова маршрутизація (File System Routing)

У NaN•Web шлях у файловій системі є єдиним джерелом істини для адресації додатку (маршруту/роуту).

### Як це працює:

- Будь-який файл даних (наприклад, `data/uk/private/cards/Visa-Infinite.html` або `data/uk/index.nan0`) є кінцевою точкою маршруту.
- Файл самостійно визначає у своїй структурі, яка **Доменна Модель додатка** або **Модель представлення (ViewModel)** має бути ініціалізована на цьому екрані.

### Приклад конфігурації у файлі сторінки:

```yaml
# data/uk/private/cards/Visa-Infinite.nan0
title: 'Visa Infinite — Картка'
appModel: 'CardDetailsApp'
viewModel: 'CardDetailsViewModel'
data:
  cardId: '73'
  currencies: ['UAH', 'USD', 'EUR']
  limits:
    withdrawal: 50000
```

Коли користувач переходить за адресою `/private/cards/Visa-Infinite.html`, системний роутер зчитує цей файл, автоматично створює екземпляр `CardDetailsApp` з переданими `data`, і передає інтенції адаптеру для рендерингу.

---

## 🗄️ Гнучка архітектура збереження даних

Хоча базові шаблони NaN•Web використовують плоскі NaN•документи у папці `data/`, архітектура додатків повністю абстрагована від конкретного способу збереження.

Доменна модель може отримувати дані з будь-якого джерела:

- **Локальні NaN•документи** (через утиліту `DBFS` або локальний R/W буфер).
- **Бази даних** (PostgreSQL, SQLite).
- **Сховища Key-Value** (Redis) для швидкої синхронізації стану.
- **Шорд-сервери або децентралізовані сховища** (IPFS).

З точки зору ОLMUI, сховище даних є лише провайдером конфігурацій, який модель використовує під час запуску методу `run()`.
