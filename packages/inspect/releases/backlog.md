# Беклог @nan0web/inspect

## 🎯 Заплановані можливості (Backlog)

### 1. Адресний аудит та Scoped / Git-Diff режим (`--file`, `--diff`)
- **Проблема:** У великих монорепозиторіях або додатках зі спадковим кодом `nan0inspect` (зокрема `JsDomainAuditor`) сканує абсолютно всі файли `src/domain/**`. Повідомлення про застарілі класи переповнюють буфер виводу консолі, що маскує помилки поточного релізу і змушує агента працювати наосліп.
- **Вимоги:**
  - Підтримка CLI прапорця `--file=<path>`: запуск перевірки для одного конкретного файлу або папки (наприклад, `nan0inspect domain --file=src/domain/commands/TranscribeCommand.js`).
  - Підтримка `--staged` або `--diff`: перевірка виключно тих файлів, що змінені в поточній git-гілці/релізі.
  - Лаконічний звіт (без спаму повторюваними повідомленнями).

### 2. Аудит сервісних інжекцій (`this.$*`)
- **Проблема:** Сервіси та провайдери з `options` іноді помилково призначаються у звичайні поля `this.service`, що плутає їх із полями даних `Model-as-Schema` або створює антипатерни з надлишковими геттерами.
- **Вимоги:**
  - Перевіряти, що будь-які зовнішні провайдери/сервіси з `options` призначаються виключно у властивості з префіксом `this.$` (наприклад, `this.$db`, `this.$UI`, `this.$whisperService`).
  - Вимагати явний контракт типів у JSDoc: `/** @type {typeof WhisperTranscriptionService} */ this.$whisperService` (заборона `any`).
