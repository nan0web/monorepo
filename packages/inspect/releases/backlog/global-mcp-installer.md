# 🌐 Глобальне налаштування MCP для редакторів (`--global`)

> **Статус:** Planned / Backlog  
> **Пакет:** `@nan0web/inspect`  
> **Компоненти:** `InstallApp`, `DoctorApp`  

---

## 🎯 Проблема

Наразі `nan0inspect install` за замовчуванням записує MCP-конфігурацію локально у проєктний каталог (`.cursor/mcp.json`, `.vscode/settings.json`). 
Користувачі та архітектори часто очікують **глобального** підключення інструментів інспектора на рівні операційної системи / користувача, щоб інспектор був доступний у будь-якому проєкті без генерації локальних конфігураційних файлів у корені робочого репозиторію:
1. Для Cursor IDE: `~/.cursor/mcp.json` або глобальні налаштування.
2. Для VS Code: глобальний `settings.json` користувача (`~/Library/Application Support/Code/User/settings.json` на macOS, `%APPDATA%/Code/User/settings.json` на Windows).
3. Якщо команду запущено з підкаталогу монорепозиторію (наприклад, з `packages/inspect`), вона наразі шукає `.vscode` відносно поточної робочої директорії, а не кореня монорепо.

---

## 📋 Вимоги та Функціонал

1. **Прапорець `--global` (`-g`):**
   - `nan0inspect install --global` записує конфігурацію MCP у глобальний профіль користувача Cursor та VS Code.
2. **Автодетекція кореня репозиторію:**
   - Якщо інсталяція запускається без `--global`, резолвити проєктні `.cursor` та `.vscode` не від `process.cwd()`, якщо це підпапка, а від знайденого кореня монорепозиторію (де лежить корінний `package.json` або `.git`).
3. **Діагностика через `doctor`:**
   - `nan0inspect doctor` має явно показувати рівень конфігурації: `Global` vs `Project-level`.
