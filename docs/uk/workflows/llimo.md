# 🎼 Мережевий Оркестратор: /llimo

Це головний і **єдиний** воркфлоу, який ти (Antigravity Agent) маєш використовувати для розробки нових додатків або систем OLMUI у поточному вікні, емулюючи роботу майбутнього `llimo.app`. 

Відтепер, коли користувач звертається із ТЗ на створення чогось нового, ти забуваєш про всі старі довжелезні 9-крокові пайплайни (вони застарілі та видалені). Ти дієш швидко, агресивно та інтелектуально, використовуючи нижченаведений алгоритм "Antigravity as LLiMo":

## 1. Фаза Аналізу та RAG (Knowledge Fetch)
Ти не кидаєшся відразу писати код "з нуля" чи генерувати `index.html`.
- **Запит до Бази**: Обов'язково використовуй інструмент `mcp_nan0web-knowledge_search_knowledge_base`, щоб пошукати у локальному індексі існуючі фрагменти, які б підійшли під запит (наприклад, моделі `auth`, `editor`, `core` чи `finance`). 
- **Tag Matching**: Якщо користувач хоче "систему фінансів", знайди тег `finance` чи `db` і потягни ці моделі.

## 2. Формування Domain-Моделі (The Core)
Після обробки RAG-інформації:
- Створи або онови файл `project.md` у новому пакеті.
- Згенеруй єдине правильне джерело правди: `Models.js` як Schema, керуючись архітектурою `Model-as-Schema`. Жодного жорстко закодованого (hardcoded) UI/тексту. Всі дані лежать у YAML / Моделях.

## 3. Генерація UI для nan0web.app Runner (The Webview)
- Ми робимо крос-платформний інтерфейс виключно на базі `ui-lit` (Web Components) або чистого HTML. **Жодного React.**
- Інтерфейс підключається так, щоб він одразу працював у `nan0web.app` (який виступає універсальним ранером).
- Згенеруй `index.html` або `.play.js` для візуальної верифікації (Пісочниця).

## 4. Voice Feedback Protocol (Звітність)
Під час переходу між етапами (RAG -> Domain -> UI), а також при завершенні завдання, **обов'язково** використовуй інструмент `run_command` для генерування короткого голосового сигналу (згідно з `/voice-feedback-protocol`), наприклад:
```bash
say -v "Lesya (Enhanced)" "Знайшов залежності в базі. Генерую моделі."
```
Твоя відповідь у текстовому чаті має бути лаконічною (лише суть і дифи), основний об'єм даних лежить у файлах.

## ⚠️ Правила Обробки Запитів:
1. Якщо введено голосовий намір — ти його автоматично розпізнаєш і запускаєш процес (без зайвих текстових підтверджень, якщо задум ясний).
2. Якщо індекс не дав результату — створюй з мінімальних примітивів, використовуючи `0HCnAI` патерни.
3. Економимо ресурси. Замість довгих дискусій просто генеруй прототип. Користувач переглядатиме його у сусідньому вікні (`nan0web.app`).
