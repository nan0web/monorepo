# 🎼 Мережевий Оркестратор: /llimo

Це головний і **єдиний** воркфлоу, який тИ (LLM Dev Agent) маєш використовувати для розробки нових додатків або систем OLMUI у поточному вікні, емулюючи роботу майбутнього `llimo.app`.

## 1. Фаза Аналізу та RAG (Knowledge Fetch)

Ти не кидаєшся відразу писати код "з нуля" чи генерувати `index.html`.

- При вивчені API функціоналу додатку **вивчай в першу чергу** опис функцій, для javascript це можуть бути згенеровані типи `.d.ts`, `.d.tsx`, для cpp це `.h`, `.hpp`, для python це `.pyi` або просто документація.
- **Запит до Бази**: Обов'язково використовуй інструмент `mcp_nan0web-knowledge_search_knowledge_base`, щоб пошукати у локальному індексі існуючі фрагменти, які б підійшли під запит (наприклад, моделі `auth`, `editor`, `core` чи `finance`).
- **Tag Matching**: Якщо користувач хоче "систему фінансів", знайди тег `finance` чи `db` і потягни ці моделі.

**Сформуй правильний і достатній контекст.**

Якщо недостатньо - запитай у користувача.

## 2. Формування Доменної Моделі (Domain Core)

Після обробки RAG-інформації:

- Створи або онови файл `project.md` або `docs/{locale}/project.md` у новому пакеті.
- Згенеруй єдине правильне джерело правди: `Models.js` як Schema, керуючись архітектурою `Model-as-Schema`. Жодного жорстко закодованого (hardcoded) UI/тексту. Всі дані і переклади лежать у YAML / NaN0 / Моделях.

## 3. Генерація UI для nan0web.app Runner (Веб-перегляд та рендерери)

- В залежності від проєкта мИ обираємо потрібні нам інтерфейси з усіх можливих і описаних у [`ui`](/packages/ui/).
- Інтерфейс підключається так, щоб він одразу працював у `nan0web.app` (який виступає універсальним ранером).

## 4. Шлюзи Якості та Цикл Самовідновлення (Quality Gates Loop)

Перед завершенням будь-якої фази або показом результату користувачу, агент зобов'язаний виконати конвеєр перевірок, що унеможливлює передачу поламаного коду:

1. **Передпольотний базовий шлюз (Pre-flight Baseline Gate)**: Перевірити, що початковий проєкт зелений (`git status -s` та `pnpm test:all`), перш ніж вносити зміни.
2. **Швидкі пофайлові шлюзи (Fast Per-File Gates)**:
   - `node --check <file>`: перевірка синтаксису (JS/MJS).
   - `prettier --check <file>`: перевірка форматування та гігієни розширень (кожен проєкт може мати власний `.prettierrc`).
   - `node --test <test_file>`: запуск тільки пов'язаного unit-тесту зміненого файлу.
   - `tsc --noEmit <file>`: перевірка контрактів і типів TypeScript/JSDoc.
3. **Контекстний інтеграційний шлюз (Context Integration Gate)**: Запуск усіх тестів, зареєстрованих у контексті задачі (`chat.context.files`). Викликається **лише** після успіху пофайлових шлюзів.
4. **Повний шлюз тестів проєкту (Full Project Test Gate)**: Запуск `pnpm test:all` (якщо не вимкнено `skipProjectTests`). Викликається **лише** після успіху контекстного шлюзу.
5. **Шлюз архітектурної інспекції (Architectural Inspection Gate)**: Запуск валідаторів `@nan0web/inspect` (`pnpm run inspect:all`). Викликається **лише після того**, як усі тести 100% зелені.
6. **Цикл самовідновлення (Self-Healing Loop)**: Якщо виявлено помилку, агент додає її до `chat.addError(...)` та автоматично виправляє файл до вичерпання спроб (`maxRetries`), після чого запитує підтвердження користувача через `ask('autoContinue')`.

## 5. Протокол Голосового Зв'язку (Voice Feedback Protocol)

Під час переходу між етапами (RAG -> Domain -> UI -> Quality Gates), а також при завершенні завдання, **обов'язково** використовуй інструмент `run_command` для генерування короткого голосового сигналу (згідно з [voice-feedback-protocol.md](./voice-feedback-protocol.md)), наприклад:

```bash
say -v "Lesya (Enhanced)" "Знайшов залежності в базі. Генерую моделі. Виконано 20% задачі."
```

Твоя відповідь у текстовому чаті має бути лаконічною, основний об'єм даних лежить у файлах.

2. Якщо пошук у базі не дав результату — створюй компоненти і моделі з мінімальних примітивів, спираючись на еталонні шаблони та рецепти:
   - **Доменні моделі-схеми**: [model-schema.md](./model-schema.md)
   - **OLMUI CLI додатки**: [model-as-app-cli.md](./model-as-app-cli.md) та [model-as-app.md](./model-as-app.md)
   - **Сценарні тести (TDD First)**: [olmui-scenario-test.md](./olmui-scenario-test.md)
   - **Канонічні шаблони релізів та планів**: `docs/uk/templates/plan.md`, `docs/uk/templates/backlog.md`, `docs/uk/templates/release.md`
   - **Самоаудит**: [self-audit-protocol.md](./self-audit-protocol.md)

4. Користувач переглядатиме прототип у сусідньому вікні (`nan0web.app`).
