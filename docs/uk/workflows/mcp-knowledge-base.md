# MCP Knowledge Base Protocol (Vector DB Search)

**Вступ:**
Цей воркфлоу визначає суворі правила пошуку інформації та ресурсів у внутрішній Базі Знань екосистеми NaN0Web за допомогою векторної бази даних (VectorDB) та інструментів Model Context Protocol (MCP).

## 🛑 Головне Правило (The Golden Rule)

**НІКОЛИ не використовуйте `grep`, `find`, або `nan0ai search` в терміналі для пошуку документації або концептуальної інформації!**
**НІКОЛИ не просіть у користувача дозволу на доступ до файлів, якщо ви можете отримати їх через MCP!**

Замість цього, **ЗАВЖДИ** використовуйте вбудовані інструменти MCP сервера `nan0web-knowledge`. Це безпечніше, швидше (без затримок на підтвердження) і використовує семантичний (RAG) пошук.

## 🛠 Доступні Інструменти MCP

Агент (AI) має доступ до наступних інструментів (tools):

1. `mcp_nan0web-knowledge_search_knowledge_base`
2. `mcp_nan0web-knowledge_get_resource`

### 1. Пошук інформації (Search)

Коли вам потрібно знайти архітектурні рішення, правила, воркфлоу, описи компонентів чи будь-яку іншу документацію:
Викликайте інструмент `mcp_nan0web-knowledge_search_knowledge_base`.

**Параметри:**

- `query` (обов'язково): Ваш пошуковий запит (напр., "як додати editor.app", "правила i18n", "architechnomag workflow"). Запит може бути англійською або українською.
- `k` (опціонально): Кількість результатів (за замовчуванням 5).
- `projects` (опціонально): Масив назв проєктів, якщо хочете обмежити пошук конкретним пакетом (напр., `["@nan0web/ui"]`).

**Очікуваний результат:**
Ви отримаєте масив знайдених фрагментів (snippets) у форматі Markdown. Якщо релевантної інформації недостатньо, спробуйте перефразувати `query` або змінити `k` чи розширити `projects`.

### 2. Отримання повного ресурсу (Get Resource)

Якщо пошук або користувач надав вам логічний чи відносний шлях до документації (наприклад, `@nan0web/ui/src/index.js` або `docs/project.md`), і вам потрібно прочитати його повністю:
Викликайте інструмент `mcp_nan0web-knowledge_get_resource`.

**Параметри:**

- `path` (обов'язково): Логічний шлях до ресурсу.

## 💻 Термінальні інструменти пошуку (CLI Tools)

Окрім MCP, у терміналі доступний інструментарій `nan0ai` для глибокого аналізу воркспейсу та пошуку по сирцях (типах):

### 1. Перегляд стану індексів (Show Index)
Використовуйте для перевірки, які пакети вже проіндексовані та в якому обсязі:
`nan0ai show index` (або просто `nan0ai show`)

### 2. Пошук по типах та сирцях (Search Sources)
Коли вам потрібно знайти конкретні класи, методи чи типи у `.d.ts` файлах:
`nan0ai search "class Name" --sources --strict`

**Параметри:**
- `--sources` (або `-s source`): Шукати в області сирців (типи `.d.ts`).
- `--strict` (або `--strictSearch`): Точний збіг рядка (без векторного наближення), ідеально для пошуку назв класів.

### 3. Оновлення індексу (Index)
Якщо результати застаріли або відсутні:
`nan0ai index -s source -p "@nan0web/i18n" -f` (індексує лише один вказаний пакет)

### ❓ Допомога по командах (Help)
Завжди можна переглянути повний список доступних опцій та параметрів для будь-якої команди:
`nan0ai search --help`
`nan0ai index --help`
`nan0ai show --help`

## 💡 Чому це важливо? (Zero-Hallucination)

- **Швидкість:** MCP інструменти працюють миттєво і не вимагають апруву користувача на виконання bash-команд.
- **Точність:** Векторна база даних враховує контекст (embeddings), а не просто збіг рядків. Вона автоматично групує та повертає лише семантично релевантні шматки коду або тексту.
- **Безпека:** Відсутність ризику випадково зламати або видалити файли через некоректні команди в терміналі.

## 🔄 Інтеграція з іншими воркфлоу

Цей воркфлоу є фундаментальним. Він повинен викликатися _першим_ при зіткненні з будь-якою невідомою концепцією NaN0Web (наприклад: Model-as-Schema, Zero-Tolerance, Anti-Haste, OLMUI).
