# 🗂 Ворклоу: Indexator (Екосистемний Індекс)

Цей workflow описує автоматизований і детермінований процес підтримки в актуальному стані центральних індексів екосистеми: `packages/index.md` та `apps/index.md`.

## 1. Концепція Indexator (Zero-LLM)

Індексування пакетів **не використовує** мовні моделі (ніяких субагентів чи "вигадок" описів).
Замість цього, Indexator спирається на жорстко структуровані файли `project.md` у кожному пакеті/додатку і витягує дані за мілісекунди.

## 2. Вимога до `project.md` (Джерело правди)

Щоб Indexator міг працювати миттєво, кожен `project.md` в екосистемі **ОБОВ'ЯЗКОВО** повинен мати `YAML frontmatter` на самому початку файлу.

**Приклад `packages/my-module/project.md`:**

```markdown
---
description: Маршрутизатор UI для обробки подій з терміналу (CLI).
tags: [ui, cli, router]
---

# 🏗️ Філософія my-module

...
```

## 3. Алгоритм Роботи (Execution Logic)

При виклику цього воркфлоу, скрипт індексатора виконує наступне:

1. Сканує директорії `packages/` та `apps/` (рівень 1).
2. Знаходить там усі файли `project.md`.
3. За допомогою Regex (наприклад: `/^description:\s*(.+)$/m`) витягує опис і теги пакету з Frontmatter.
4. Якщо `project.md` відсутній або не має `description` — використовується ім'я папки, але кидається попередження.
5. Генерує Markdown-таблицю або список.
6. Перезаписує `packages/index.md` та `apps/index.md` єдиною дією.

## 4. Інтеграція та Виклик

Коли агент розробляє новий пакет або повністю змінює існуючий, він МАЄ:

1. Забезпечити наявність правильного frontmatter у `project.md`.
2. Запустити скрипт індексації (через `run_command` Node.js скрипту індексації, або через NPM-команду якщо така наявна).

Це гарантує, що наступні агенти, запускаючи `@[/seed-analysis]`, отримуватимуть 100% точний і компактний список усіх існуючих модулів у всій екосистемі, уникаючи дублювання та галюцинацій.
