# 🏭 `app-pipeline-09-qa` (Final Assembly & QA)

> **Призначення:** Дев'ятий (фінальний) крок конвеєра. Зшивання даних, i18n та повна перевірка якості.

## Інструкція для Агента

Коли Архітектор викликає цей workflow:

1. **i18n Екстракція та Верифікація:**
   - Переконатися, що всі англійські рядки з Моделі винесені в конфіг `data/uk/_/t.yaml`.
   - Запустити QA-бота [inspect-i18n](./inspect-i18n.md) для повної перевірки перекладів.

2. **Сценарні Тести та Snapshot-Покриття (User Stories):**
   - Базова перевірка: Переконатися, що існують базові `*.story.js` тести для перевірки доменної логіки та інтенцій (Intents) моделей.
   - **Full UI Coverage:** Для **кожного** реалізованого шару UI (CLI, Chat, Web, Mobile) перевірити наявність відповідних Snapshot-тестів (`*.cli.story.js`, `*.web.story.js` тощо), які проганяють ці ж User Stories через конкретний інтерфейс.
   - Згенерувати/оновити Golden Master снапшоти. Людина лише візуально підтверджує, що тести пройшли і снапшоти коректні.

3. **Архітектурна та Лінкова перевірка (Експорти):**
   - Перевір чи `package.json` належним чином експортує файли.
   - Запустити [/inspect-structure](./inspect-structure.md) для контролю зв'язків.
   - Запустити `bin/inspect-links.js` через `npm run test:all`.

4. **Гігієна та Очищення (100% Zero-Hallucination):**
   - Запустити `npm run knip` для очищення `package.json` від мертвих залежностей.
   - **ОБОВ'ЯЗКОВО:** Видали тимчасовий `seed.md` (якщо є), щоб підготувати чисте місце. Переконайся, що всі фази `project.md` зелені.

## Результат:

Ти гарантуєш, що додаток НЕ має:

- Злагоджених текстів (все зашито в Модель).
- "Висячих" файлів.
- Код-смеллів у `Adapter.js`.
