# 📊 Парадигми Розробки та Формула Інженерної Ефективності (SpecDevOps & NaN•Web)

Цей документ формалізує порівняльний аналіз сучасних підходів до розробки софту з використанням AI, вводить точну цифрову формулу інженерної ефективності (EEF) із врахуванням витрат ресурсів (повідомлення, токени, розмір контекстного вікна), аналізує ризики публічних безкоштовних API (NVIDIA NIM) та закріплює протокол **Fast Fuzzy Lookup** для агентів платформи NaN•Web.

## 2. Повна Формула Інженерної Ефективності (EEF)

Формула розраховує підсумкову ефективність з урахуванням якості архітектури, штрафів за деградацію та коефіцієнта ресурсоємності (токени, кроки, вікно):

$$EEF = \left[ \sum_{i=1}^{n} (S_i \cdot W_i) \right] \cdot \Big(1 - \frac{H_r + R_e}{2}\Big) \cdot C_{res}$$

### Складові формули:
1. **$S_i \in [0, 10]$** — оцінка за критеріями якості:
   - Детермінізм результату ($W_1 = 0.20$)
   - Архітектурний контроль ($W_2 = 0.15$)
   - Збереження перекладів i18n ($W_3 = 0.15$)
   - Стійкість до Pre-training Curse ($W_4 = 0.15$)
   - Безпека I/O та ізоляція ($W_5 = 0.15$)
   - Швидкість повного циклу TCO ($W_6 = 0.10$)
   - Автономність без деградації ($W_7 = 0.10$)
2. **$H_r \in [0, 1]$ (Hallucination Rate)** — частка дій на здогадках замість контрактів.
3. **$R_e \in [0, 1]$ (Regression Error)** — штраф за спроби ламати архітектуру (сирий `fs`, хардкод шляхів, дублювання).
4. **$C_{res} \in (0, 1]$ (Resource Efficiency Coefficient)** — коефіцієнт витрати ресурсів:
   $$C_{res} = \frac{1}{1 + \alpha \cdot \frac{T}{100k} + \beta \cdot \frac{M}{10}}$$
   де $T$ — витрачені токени, $M$ — кількість повідомлень (turns), $\alpha=0.05, \beta=0.05$.

## 4. Чому розробка в NaN•Web здається «повільнішою», але обганяє інші підходи?

### Психологічна пастка «Швидкого старту» (The Illusion of Speed)
1. **Prompt-driven (Cursor / Copilot):**
   - *Хвилини 0–5:* Ейфорія від 500 згенерованих рядків коду.
   - *Години 1–10:* Нескінченне налагодження (Debugging Tax), зниклі переклади, порушення модульності, вичерпання контекстного вікна.
2. **Adaptive Graph (LangGraph / MetaGPT):**
   - Спалює сотні тисяч токенів у розмовах агентів між собою. Що більше агентів, то вищий ризик взаємної дезінформації та неконтрольованого стану.
3. **NaN•Web SpecDevOps:**
   - *Етап 1 (Bootstrap & Contracts):* Інвестиція часу в `task.md`, `task.spec.js` та типи V8 Shapes. Суб'єктивно це відчувається як сповільнення, бо пишеться специфікація перед кодом.
   - *Етап 2 (Execution):* Детерміноване проходження TDD Red-Green та перевірка лінтерами `nan0inspect`.
   - *Етап 3 (Maintenance & Scale):* **Нульовий технічний борг**. Коли модуль створено (`@nan0web/payload-sync`), він працює як ізольований, багаторазовий LEGO-блок із 100% сумісністю.

## 5. Аналіз Безкоштовних API (NVIDIA NIM — build.nvidia.com)

При використанні публічних безкоштовних ендпоінтів (`https://build.nvidia.com/models`):
1. **Оплата даними:** За умовами *NVIDIA Technology Access Terms of Use*, вхідні промпти, завантажений код та вихідні результати **записуються і можуть використовуватись для донавчання майбутніх AI-моделей NVIDIA**.
2. **Ризик інтелектуальної власності:** Відправка закритого коду монорепозиторію на публічний build.nvidia.com юридично позбавляє його конфіденційності.
3. **Рішення для платформи:** Використання **Self-Hosted NIM** у локальних контейнерах або приватній хмарі, де телеметрія та промпти не виходять за межі внутрішньої мережі.

## 6. Протокол Fast Fuzzy Lookup (CAD Protocol)

Закріплений у кодексі платформи: `docs/uk/workflows/codebase.md` та `.agents/AGENTS.md`.
1. **Зчитування Master Index (`docs/uk/workflows/README.md`)** за ключовими словами (`db`, `model`, `release`, `inspect`).
2. **Фізичний виклик `read_file`** знайденого workflow файлу перед виконанням завдань.
3. **Уточнення через `ask_question`** за наявності неоднозначностей.
4. **Фіксація в шапці АрхіТехноМага** як гарантія відповідності інженерним стандартам платформи.
