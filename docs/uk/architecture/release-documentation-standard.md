# 📚 Стандартизація Документообігу Релізів: Повна Специфікація Артефактів

> **Статус:** 🟢 Канонічний стандарт монорепозиторію NaN0Web  
> **Зв'язок з пайплайном:** Сумісний з 9-кроковим майстер-конвеєром OLMUI (`app-pipeline-01-seed` → `app-pipeline-09-qa`)

## 🧭 1. Повна Карта Артефактів Релізу

Усі документи та файли, що беруть участь у процесі розробки та фіксації релізу, мають суворе призначення:

| Файл / Артефакт | Назва та Суть | Коли створюється та заповнюється? | Що містить? |
| :--- | :--- | :--- | :--- |
| **`backlog.md`** | **Загальний Беклог (Master Backlog)** | Знаходиться в корені `releases/backlog.md` | • Вхідний пул ідей (Feature Requests)<br>• Розподіл задач по майбутніх релізах<br>• Icebox / Дослідження |
| **`release.md`** | **Паспорт Релізу (Release Manifest)** | Створюється на старті версії (`release init vX.Y.Z`) | • User Stories під ролі (Admin/User/Dev)<br>• Список задач та матриця цільових файлів (`Target Files`)<br>• Посилання на контракти `*.spec.js`<br>• Критерії DoD |
| **`task.md`** | **Атомарна Задача / ТЗ (Atomic Task Spec)** | Створюється під окрему велику фічу або підзадачу всередині релізу | • Детальний опис конкретної фічі згідно з 9-кроковим OLMUI пайплайном<br>• YAML Frontmatter з переліком створюваних моделей |
| **`*.spec.js`** | **Контрактні Тести (TDD Red Contracts)** | Створюються на етапі планування перед написанням коду | • Виконувані тести `node:test`<br>• `it.todo()` для беклогу, `it()` для активних задач<br>• Джерело правди про стан готовності |
| **`user.md`** | **Журнал Зворотного Зв'язку та Метрик (Feedback & Telemetry Log)** | Створюється на старті релізу і ведеться **протягом усього спринту** | • Метрики витраченого часу (години)<br>• Кількість ітерацій та спроб тестів<br>• Append-Only записи зауважень Архітектора/Користувача |
| **`retro.md`** | **Фінальна Ретроспектива (Seal & Reflection)** | Створюється автоматично в момент **запечатування та закриття релізу** (`release seal`) | • Що спрацювало ідеально<br>• Які труднощі виникли та висновки<br>• Перенесені в беклог ідеї на майбутнє |
| **`*.test.js`** | **Регресійні Тести (Regression Suite)** | З'являються після закриття релізу (`release close`) | • Колишні `*.spec.js`, що мігрували у `src/test/releases/{major}/{minor}/vX.Y.Z/*.test.js`<br>• Довічний захист кодової бази від зламу |

## 🏛 2. Дворівнева Архітектура Знань

```
nan.web/ (Monorepo Root)
├── docs/uk/workflows/          # 🌐 ГЛОБАЛЬНІ СТАНДАРТИ та інструкції для AI (Workflows)
│   ├── release.md              # Загальний воркфлоу релізу (PM-as-Code)
│   ├── app-pipeline.md         # 9-кроковий Майстер-Конвеєр (OLMUI)
│   ├── model-as-app.md         # Загальний воркфлоу консольних моделей
│   └── ...
├── docs/uk/templates/          # 📋 КАНОНІЧНІ ШАБЛОНИ (Templates)
│   ├── backlog.md              # Шаблон загального беклогу
│   ├── release.md              # Шаблон паспорту релізу
│   └── user.md                 # Шаблон журналу зворотного зв'язку
│
└── packages/release/           # 📦 ПАКЕТ ІМПЛЕМЕНТАЦІЇ (@nan0web/release)
    ├── system.md               # Інструкція розробника конкретного пакета
    ├── project.md              # Архітектура пакета
    └── docs/uk/README.md       # API-документація, CLI команди та приклади коду
```

### Чому саме так:
1. **`docs/uk/workflows/` (Глобально):** Єдине джерело правди для всіх додатків і пакетів. AI-агенти та розробники завжди знають, де знайти процес.
2. **`packages/release/` (Локально):** Містить програмний код інструментів (`Scanner`, `ReleaseManager`, CLI `nan0release`), які автоматизують цей процес.
