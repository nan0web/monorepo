# 📋 Журнал Зворотного Зв'язку Користувача (User Requirements Log)

Цей документ фіксує всі зауваження, вимоги та виправлення, внесені на основі зворотного зв'язку користувача. Будь-які нові помилки або зміни вимог мають обов'язково покриватися тестами.

---

### 1. Перехід на пробіли у підкомандах замість двокрапки
* **Опис звернення**: Уникнути використання двокрапок у підкомандах (наприклад, `strategy:list`), оскільки OLMUI архітектура вже підтримує послідовне розділення пробілами.
* **Вжиті заходи**:
  - Створено контейнерну модель `StrategyApp` (alias: `strategy`).
  - Оновлено аліаси підкоманд на чисті слова (`list`, `add`, `remove`, `edit`).
  - Реалізовано очищення `data.command` від імені батьківської команди у конструкторі `StrategyApp` для коректної маршрутизації позиційних аргументів.
  - Додано тест `should route commands in StrategyApp container model` у `AiStrategyModel.test.js`.

### 2. Усунення фігурних дужок у CLI виводах (Template Patterns)
* **Опис звернення**: Багато слів у CLI виводяться загорнутими у фігурні дужки `{...}`, замість підстановки реальних значень.
* **Причина**: Помилка регулярного виразу у функції `t()` в `bin/llimo.js`, яка робила фігурні дужки необов'язковими (`\{?`), через що під правила підпадали звичайні слова.
* **Вжиті заходи**:
  - Регулярний вираз виправлено на строго обов'язкові дужки: `/\{([a-zA-Z0-9_\$]+)\}/g`.
  - Додано коректний фолбек для змінних з префіксом `$`.

### 4. Оновлення черги моделей за замовчуванням (Default Cascade Queue)
* **Опис звернення**: Замінити моделі за замовчуванням під номерами 4, 5, 6 у черзі на:
  1. `deepseek/deepseek-v4-flash:free@openrouter`
  2. `nvidia/nemotron-3-nano-30b-a3b:free@openrouter`
  3. `openai/gpt-5.4-nano@openrouter`
* **Вжиті заходи**:
  - Оновлено статичне поле `AiStrategyModel.cascadeQueue.default` у `AiStrategyModel.js`.

### 5. Підтримка передачі довільного запиту (Prompt Fallback)
* **Опис звернення**: При виклику `node bin/llimo.js "Створи React компонент"` додаток завершував роботу без результату, оскільки сприймав промпт як невідому команду.
* **Вжиті заходи**:
  - У конструкторі `LlimoApp.js` додано перехоплення: якщо переданий `command` є рядком (промптом) і не збігається з підкомандами, він передається як `input` до автоматично створеного `ChatSessionModel`.
  - Додано тест `should instantiate ChatSessionModel with prompt input if no matching subcommand is found` у `LlimoApp.test.js` для перевірки цієї поведінки.

### 6. Обов'язкове покриття тестами
* **Вимога**: Кожне виправлення знайдених помилок має покриватися автоматичними тестами, щоб зафіксувати стабільність раз і назавжди.
* **Вжиті заходи**:
  - Будь-які зміни в логіці каскадування, boundary або підкоманд супроводжуються валідацією через відповідні `.test.js` файли.

### 7. Підключення/Додавання файлів до контексту (Context Packing)
* **Опис звернення**: Забезпечити можливість додавати файли до контексту промпту (наприклад, файли з пропозиціями або шаблонами).
* **Вжиті заходи**:
  - Розширено логіку `packInput` у `ChatSessionModel.js`. Тепер додаток:
    1. Автоматично зчитує та розкриває файлові посилання формату `- [назва](шлях)` у тексті промпту або вхідного файлу.
    2. Зчитує додаткові позиційні файли, передані через командний рядок (наприклад, `node bin/llimo.js "Створи компонент" src/Template.js`), та додає їх у контекст промпту.
  - Додано юніт-тест `should pack input and positionals files correctly` у `ChatSessionModel.test.js`.

### 8. Інтерактивне меню після генерації (Post-Execution Verification Menu)
* **Опис звернення**: Дати можливість запускати тести та workflow інспектори (валідатори) після генерації файлів у інтерактивній сесії.
* **Вжиті заходи**:
  - Додано інтерактивне меню після успішної генерації чи зміни файлів (якщо запуск відбувається у TTY-консолі, поза тестами).
  - Користувач може обрати:
    1. `Run tests (pnpm test)` — запустити тестовий набір проєкту.
    2. `Run linter/formatter check (npm run lint)` — запустити перевірку стилю коду.
    3. `Run project validators (pnpm test:validate)` — запустити валідатори структури та архітектури NaN0Web.
    4. `Continue chat session` — продовжити інтерактивний діалог.
  - Результат перевірки виводиться у вигляді **однорядкової статистики** (наприклад, для Node.js тестів: `tests: 32, suites: 16, pass: 32, fail: 0, duration: 250.46ms`), щоб не засмічувати консоль довгими логами.
  - Якщо вибраний крок перевірки виконано **успішно** (exit code 0), сесія чату автоматично завершує роботу. Якщо крок завершився помилкою, користувач повертається до меню вибору, що дає змогу виправити помилки та повторити запуск.

### 9. Підтвердження збереження файлів перед записом на диск (Confirm Save Files)
* **Опис звернення**: Файли зберігалися на диск до запиту підтвердження, через що при відхиленні (No або Cancel) зміни все одно записувалися.
* **Вжиті заходи**:
  - Перед будь-яким записом файлів додано виклик підтвердження `confirm_save_files`.
  - Якщо користувач обирає `No` або скасовує промпт, файлові зміни відкидаються, виводиться попередження `File changes discarded`, і запис скасовується.
  - Усі системні `show()` повідомлення перекладено на локалізовані ключі в статичному об'єкті `ChatSessionModel.UI`.

### 10. Обмеження виконання консольних команд тільки для блоків `@bash`
* **Опис звернення**: Система намагалася виконати рядки з блоку `@validate` як консольні команди (наприклад, `apps/share.app/src/domain/TelegramAdapter.js?`).
* **Вжиті заходи**:
  - Обмежено парсинг та виконання консольних команд виключно для блоків з назвою `@bash`.
  - Інші службові блоки (наприклад, `@validate`, `@ls`, `@get`, `@workflow`) більше не обробляються як набір консольних команд.

### 🔮 Відкладене рішення: Поліморфна верифікація (VerifyModel)
* **Контекст**: Розглянуто рефакторинг блоку верифікації після генерації (test/lint/validate) на поліморфну ієрархію моделей з детекцією стеку (Js/Py) через `StackDetector` з `@nan0web/inspect`.
* **Рішення**: **Відкладено.** Зараз існує лише один стек (JS). Створення 8 файлів з ієрархією наслідування для заміни 60 рядків — передчасна оптимізація.
* **Успадкування `AuditorModel`**: Не підходить. `AuditorModel` — для інспекції коду (аналіз файлів, пошук порушень). Верифікаційні дії — це «запусти команду, покажи результат». Різні домени.
* **Тригер для повернення**: Коли з'явиться реальна потреба у Python/Go/Rust верифікації, або кількість дій суттєво зросте (typecheck, e2e, benchmark), або `verify` стане окремою CLI-підкомандою (`llimo3 verify test`).
