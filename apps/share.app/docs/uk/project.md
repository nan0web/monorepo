# Проєкт: @nan0web/share.app — Суверенний Шар Дистрибуції (Rules Engine)

> **Статус:** 🟢 100% Верифіковано (Green Build)
> **Стандарт:** Zero-Hallucination Architectural Guidelines
> **Архітектура:** One Logic — Many UI (OLMUI)

---

## 🗺️ Фаза 1: Намір та Seed (Intent & Seed)

### 1.1 Бізнес-Намір
`@nan0web/share.app` — це автономне рішення для автоматичного розподілу публікацій у соціальних мережах (дистрибуції контенту) на основі декларативних правил та інтелектуального планування затримок. Головна мета — відокремити бізнес-логіку правил публікацій від особливостей конкретних платформ (Telegram, RSS, Twitter/X) та забезпечити передбачуване планування публікацій.

### 1.2 Seed-вимоги та Межі
- **Декларативні правила (Rules Engine)**: Публікації фільтруються на основі умов (`if`) — теги (`tags`), мова (`lang`), тип (`type`), медіа-вміст (`hasMedia`).
- **Сценарні затримки (Delay Planner)**: Підтримка декларативних інтервалів: відносні (хвилини `30m`, години `2h`), абсолютні (`1d 09:00`), або прив'язані до дня тижня (`Mon 10:00`).
- **Строгий Контракт Адаптерів**: Кожен адаптер соцмереж зобов'язаний розширювати інтерфейс `SocialAdapter` та декларувати ліміти (`limits`) й можливості (`capabilities`).
- **Zero-Hallucination структура**: Логіка ядра та адаптерів суворо ізольована в каталозі `src/domain/` та `src/adapters/` відповідно.

## 🗂️ Фаза 2: Моделі та Дані (Models & Domain Vocabulary)

Всі структури даних у системі є суворо типізованими спадкоємцями базового класу `Model` (патерн **Model-as-Schema**). Вони декларують свої поля статично, що дозволяє автоматично генерувати документацію (метод `Model.describe()`).

### 2.1 Core Моделі (`src/domain/Models.js`)

1. **`SocialAdapterConfig`**:
   Базовий клас конфігурації для будь-якого адаптера соціальних мереж. Декларує обов'язкові поля:
   - `id`: Унікальний ідентифікатор адаптера.
   - `account`: Назва облікового запису / каналу.

2. **`SocialAdapterLimits`**:
   Описує технічні обмеження платформи:
   - `maxLength`: Максимальна довжина текстового повідомлення (за замовчуванням `Infinity`).

3. **`SocialAdapterContent`**:
   Представляє вхідний вміст для публікації. Проводить сувору валідацію:
   - `text`: Текст публікації.
   - `photo`: URL-адреса фото.
   - `document`: URL-адреса супутнього документа.
   - `tags`: Масив тегів.
   - `type`: Тип публікації (`post`, `article` тощо).
   - `lang`: Дволітерний код локалі (наприклад, `uk`, `en`).

4. **`SocialAdapterFeedback`**:
   Модель зворотного зв'язку (коментарі, реакції), що повертається при синхронізації.

5. **`SocialAdapterTarget`**:
   Цільовий об'єкт для відповідей та взаємодії.

### 2.2 Модель Адаптера Telegram (`src/adapters/TelegramAdapter.js`)

**`TelegramAdapterConfig`**:
Розширює `SocialAdapterConfig` додатковими специфічними полями для Telegram Bot API:
- `botToken`: Токен від `@BotFather`.
- `chatId`: ID каналу або чату (наприклад, `@test_channel`).
- `parseMode`: Формат розмітки тексту (`HTML` за замовчуванням).
- `disableNotification`: Тихий режим надсилання повідомлень (`false` за замовчуванням).

## 🏗️ Фаза 4: Деталі Реалізації (Implementation Details)

### 4.1 Логіка Ядра (`src/domain/`)

- **`SocialAdapter.js`**:
  Базовий протокол дистрибуції. Забезпечує перевірку можливостей за допомогою методу `can(capability)` та генерує зрозумілі помилки `NotImplementedError` при спробі виклику неперевизначених методів.
  
- **`RulesEngine.js`**:
  - `matchesConditions(content, conditions)`: Оцінює вхідний вміст за критеріями І (`AND`).
  - `parseDelay(delayStr)`: Парсить часові вирази у мілісекунди. Підтримує локальний час для виразів на кшталт `Mon 10:00` або `1d 09:00`.
  - `evaluateRules(content, rules, adapters)`: Знаходить правила, що відповідають умовам контенту, та формує чергу завдань.
  - `executeTasks(tasks, options)`: Асинхронно виконує чергу публікацій з урахуванням затримок. Перевіряє справність адаптера перед першою відправкою за допомогою `verify()`.

- **`MediaDownloadModel.js`**:
  Інтелектуальне завантаження медіафайлів (зображень, відео, аудіо та документів) за допомогою `whisper` завантажувача з інтеграцією `@nan0web/ai`.

### 4.2 Адаптер Telegram (`src/adapters/TelegramAdapter.js`)
Реалізує пряму взаємодію з Telegram Bot API через нативні HTTP-запити. Підтримує:
- Текстові повідомлення (`sendMessage`).
- Фотографії з підписами (`sendPhoto`).
- Документи (`sendDocument`).
- Оновлення тексту та підписів (`editMessageText` / `editMessageCaption`).
- Видалення повідомлень (`deleteMessage`).

### 4.3 CLI-Інструменти та Скрипти Автоматизації (bin/)

Система надає два готові до використання JS-скрипти для запуску з термінала (зареєстровані як npm-команди в `package.json`):

1. **`stats-analyzer.js`** (`npm run stats:analyze`):
   - **Призначення**: Зчитує сиру статистику YouTube Analytics (`Table data.csv` в папці `stats/`) та порівнює її з правилами у `config.yaml` / `share.config.yaml`.
   - **Аналіз**: Автоматично знаходить неактивні відео (кандидати на Unlist), довгі відео для нарізки Shorts та успішні ролики, які потребують продовження (Sequels).
   - **Гнучкість**: Підтримує автоматичне визначення шляху за наявністю конфігурації у поточному каталозі (CWD), або примусово через параметр `--root` / `-r`.
   - **Вихідний файл**: Зберігає звіт у `docs/video/stats_audit_report.md`.

2. **`script-generator.js`** (`npm run shorts:generate`):
   - **Призначення**: Автоматично створює Shorts-сценарій та промпти для відеогенератора Veo та аудіогенераторів Suno/Udio.
   - **Inference Pipeline**: Пріоритетно звертається до Cerebras `gpt-oss-120b`, з автоматичним перемиканням (fallback) на OpenRouter (`gemini-2.5-flash`) або OpenAI (`gpt-4o-mini`).
   - **Медіа**: За потреби автоматично стягує звукову доріжку вихідного відео через `yt-dlp` для локальної транскрипції.
   - **Динамічний Персонаж та Мова**: Завантажує параметри `language` (en/uk) та `character` (наприклад, `Wise Cat Zhorik` чи `Gregory Skovoroda`) з конфігурації каналу для адаптації промптів ШІ.
   - **Вихідний файл**: Створює структурований Markdown-файл сценарію `shorts_*.md` у відповідній папці епізоду з налаштованим розкладом публікації.

## 🏁 Фаза 5: Верифікація та Гігієна (Verification & Hygiene)

### 5.1 Скрипти Валідації
Проєкт містить повний набір автоматизованих перевірок у файлі `package.json`:
- `npm test`: Запуск 120 модульних тестів (протокол, адаптери, правила, парсер).
- `npm run test:docs`: Перевірка зліпків та прикладів використання з файлу `README.md.js`.
- `npm run test:integration`: Сценарна верифікація релізів v1.0.0 та v1.1.0.
- `npm run knip`: Аналіз мертвого коду та невикористаних залежностей.
- `npm run test:all`: Єдиний конвеєр перевірки (тести + документація + інтеграція + Knip).

### 5.2 Файли Гігієни
- `tsconfig.json`: Опис TypeScript типів на основі V8 JSDoc анотацій.
- `.npmignore`: Оптимальне виключення тестових файлів, чернеток та конфігів розробки з кінцевої публікації.
- `.editorconfig`: Стандартизація відступів (табуляція для JS/TS, пробіли для JSON/YAML/MD).
