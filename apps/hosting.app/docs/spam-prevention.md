# Інструкція з протидії спаму та захисту репутації IP

Цей документ визначає стандарти та практичні кроки для захисту поштових серверів `hosting.app` від використання спамерами, запобігаючи потраплянню IP-адрес платформи до чорних списків (RBL/DNSBL).

---

## 🛡️ 5-Рівнева система захисту від спаму

Для забезпечення 100% захисту репутації IP-адрес нашої хостинг-платформи впроваджується наступна політика:

### 1. Блокування вихідного порту 25 (Outbound Port 25 Block)
* **Правило:** Усі вихідні з'єднання на порт `25` закриваються на рівні фаєрволу сервера (IP tables/aaPanel WAF) для всіх клієнтських сайтів.
* **Чому це важливо:** Спамерські скрипти (наприклад, злами на WordPress) намагаються надсилати листи напряму через локальну утиліту `sendmail` на порт 25 отримувача. Блокування змушує клієнтів використовувати авторизоване підключення.

### 2. Обмеження швидкості відправки (Rate Limiting via Rspamd)
* **Правило:** На рівні Rspamd (`/etc/rspamd/local.d/ratelimit.conf`) встановлюється ліміт на відправку:
  * **Максимум:** 50 листів на годину для однієї поштової скриньки.
  * **Дія при перевищенні:** Тимчасова відмова (Greylisting) або повне відхилення запиту з кодом помилки `451 Rate limit exceeded`.

### 3. Обов'язкове налаштування SPF, DKIM та DMARC
* **SPF (Sender Policy Framework):** Дозволяє відправку листів тільки з IP нашого сервера.
  * *Приклад:* `v=spf1 a mx ip4:142.132.174.234 -all`
* **DKIM (DomainKeys Identified Mail):** Підписує кожен лист криптографічним ключем, підтверджуючи цілісність.
* **DMARC:** Визначає політику поведінки при отриманні неавторизованого листа (наприклад, переміщення в спам або повне блокування).
  * *Приклад:* `v=DMARC1; p=quarantine; rua=mailto:admin@legalgreenplanet.tech`

### 4. Автоматичний моніторинг черги (Queue Watchdog)
Крон-скрипт кожні 5 хвилин аналізує кількість листів у черзі Postfix:
```bash
mailq | tail -n 1
```
Якщо в черзі накопичується понад 100 листів — це свідчить про спам-атаку. Скрипт надсилає сповіщення адміністратору та блокує вихідний потік підозрілого користувача до з'ясування обставин.

### 5. Вимкнення функції PHP `mail()`
У налаштуваннях PHP (`php.ini`) для всіх клієнтських сайтів відключається функція `mail()` у директиві `disable_functions`. Сайти зобов'язані використовувати виключно SMTP з авторизацією через порт 465/587.

## 🌍 Архітектурне питання: Чи потрібні два та більше MX серверів?

* **Теорія:** Наявність кількох MX записів (наприклад, `MX 10 mail.yourdomain.com` та `MX 20 backupmail.yourdomain.com`) забезпечує високу відмовостійкість. Якщо перший впаде, пошту прийме другий.
* **Практика та складнощі:** Використання кількох активних MX потребує складної синхронізації сховища листів (Maildir) та баз даних SQLite/Postgres у реальному часі. Інакше листи осядуть на бекап-сервері, і користувач не побачить їх через IMAP.
* **Рішення для SaaS хостингу:** Для тарифів за €5/місяць **одного MX сервера більш ніж достатньо**. Протокол SMTP має вбудовану чергу надійності: якщо наш сервер буде вимкнений на кілька годин, сервери відправників (наприклад, Gmail) автоматично покладуть лист у чергу і будуть повторювати спроби відправки кожні кілька годин протягом **4-5 днів**. Листи не будуть втрачені.
